# Plan v0.2 — PractiCV

Estado: **implementación cerrada**. Gmail OAuth quedó validado en vivo con una
cuenta personal en Google Personal mode. Outlook/Microsoft Graph queda como
extensión futura.

## Fase 1 — Recordatorios con Power Automate (cerrada, flujo manual)

**Objetivo:** enviar por correo el calendario `.ics` o el CSV exportado por
PractiCV.

**Implementación:** flujo instantáneo `PractiCV Recordatorios` en la cuenta
institucional; trigger manual con input de archivo y `Send an email (V2)` con adjunto.
No usa OneDrive, SharePoint, HTTP trigger ni Premium.

**Criterios de aceptación**

- [x] Flujo guardado y habilitado.
- [x] Ejecución con un export real (`calendar.ics`).
- [x] Estado `Succeeded` en el historial.
- [x] Límite documentado: es manual, no programado.
- [x] Sin correos, conexiones ni secretos en el repositorio.
- [x] Captura en `docs/assets/power-automate-run.png`.

**Evidencia:** ejecución del 2026-11-23 12:19, 985 ms, `Succeeded`. Detalle en
[`docs/power-automate.md`](power-automate.md).

**Por qué no es automático:** Microsoft retiró Power Automate para cuentas
personales (`outlook.com`) y el OneDrive del tenant institucional está bloqueado
por política. El trigger HTTP es Premium. Un flujo programado requeriría una fuente
de archivos en la nube que hoy no existe.

## Fase 2 — Bookmarklet (cerrada)

**Objetivo:** capturar la oferta que el usuario está viendo en el navegador sin
scraping masivo.

**Implementación:** el bookmarklet lee JSON-LD, título y texto visible, y abre
`/captura#<payload>` en la app local. La app previsualiza, permite editar y
confirma con `POST /offers/bookmarklet`. No guarda HTML crudo ni hace POST
cross-origin.

**Criterios de aceptación**

- [x] Botón instalable desde `/bookmarklet` en Chrome/Edge, sin extensión.
- [x] Captura una página con JSON-LD `JobPosting`.
- [x] Confirmación y edición antes de persistir.
- [x] Fallback a título/texto y avisos si falta empresa o JSON-LD.
- [x] E2E con una página cross-origin y un `JobPosting`.
- [x] Documentación en [`docs/bookmarklet.md`](bookmarklet.md).

**Evidencia:** `backend/tests/e2e/test_bookmarklet.py` (3 tests) y
`tests/e2e/phase6-bookmarklet.spec.ts`.

## Fase 3 — Correos de alerta (Gmail OAuth + `.eml`)

**Objetivo:** importar ofertas desde alertas de Gmail/Outlook sin autenticarse
en portales de empleo.

**Implementación:** Gmail OAuth con `gmail.readonly` y Google Personal mode,
token en el llavero; búsqueda de correos, preview de enlaces y filtro de ruido
de LinkedIn. Se mantiene la importación local de `.eml`.

**Criterios de aceptación**

- [x] Importación de `.eml` exportado desde Gmail/Outlook.
- [x] Gmail OAuth en vivo con `gmail.readonly` y Google Personal mode.
- [x] El usuario elige qué enlaces importar.
- [x] Deduplicación por URL/`dedupe_hash`.
- [x] Sin tokens ni credenciales en la base o en Git.
- [x] E2E con un correo HTML, un enlace duplicado y uno roto.
- [x] Filtro de enlaces de navegación de LinkedIn y normalización de jobs.
- [x] Documentación en [`docs/email-alerts.md`](email-alerts.md).
- [ ] Outlook/Microsoft Graph: extensión futura; requiere app Entra.

**Límite honesto:** el camino `.eml` funciona hoy; la bandeja conectada queda
para cuando existan credenciales. No se simula una integración no verificada.
