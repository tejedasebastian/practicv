# Plan v0.2 — PractiCV

Estado: **en curso**. Línea base: `v0.1.0` (MVP). v0.2 no reescribe el producto:
agrega captura desde el navegador, alertas, un adaptador opcional y el embudo en
Power BI. El detalle de ejecución vive en `ROADMAP.md`.

## Fase 1 — Recordatorios con Power Automate (cerrada, flujo manual)

**Objetivo:** enviar por correo el calendario `.ics` o el CSV exportado por
PractiCV.

**Implementación:** flujo instantáneo `PractiCV Recordatorios` en la cuenta
UNMSM; trigger manual con input de archivo y `Send an email (V2)` con adjunto.
No usa OneDrive, SharePoint, HTTP trigger ni Premium.

**Criterios de aceptación**

- [x] Flujo guardado y habilitado.
- [x] Ejecución con un export real (`calendar.ics`).
- [x] Estado `Succeeded` en el historial.
- [x] Límite documentado: es manual, no programado.
- [x] Sin correos, conexiones ni secretos en el repositorio.
- [x] Captura en `docs/assets/power-automate-run.png`.

**Evidencia:** ejecución del 2026-11-23 12:19, 985 ms, `Succeeded`. Detalle en
[`docs/power-automate.md`](power-automate.md).

**Por qué no es automático:** Microsoft retiró Power Automate para cuentas
personales (`outlook.com`) y el OneDrive del tenant UNMSM está bloqueado por
política. El trigger HTTP es Premium. Un flujo programado requeriría una fuente
de archivos en la nube que hoy no existe.

## Fase 2 — Bookmarklet

**Objetivo:** capturar la oferta que el usuario está viendo en el navegador sin
scraping masivo.

**Alcance:** bookmarklet que envía título, URL, JSON-LD y texto visible a
`http://localhost:8000/api/offers/capture`; el usuario confirma antes de
guardar. No guarda HTML crudo.

**Criterios de aceptación**

- [ ] Botón instalable en Chrome/Edge sin extensión.
- [ ] Captura una página fixture con JSON-LD `JobPosting`.
- [ ] Confirmación y edición antes de persistir.
- [ ] Fallback a pegar texto si no hay datos mínimos.
- [ ] E2E con una oferta real y una página sin JSON-LD.

**Riesgo:** anti-bot y cambios de HTML. Mitigación: el usuario inicia la captura
y siempre hay fallback manual.

## Fase 3 — Correos de alerta

**Objetivo:** importar ofertas desde alertas de Gmail/Outlook sin autenticarse
en portales de empleo.

**Alcance:** OAuth de solo lectura, búsqueda de alertas, selección de ofertas y
tokens en el llavero del sistema. Nada de credenciales en la base ni en Git.

**Criterios de aceptación**

- [ ] Conexión OAuth con permisos mínimos de lectura.
- [ ] El usuario elige qué correos importar.
- [ ] Deduplicación por URL/`dedupe_hash`.
- [ ] Tokens fuera del repositorio.
- [ ] E2E con un buzón de prueba y un correo sin oferta.

**Riesgo:** registro de app y consentimiento. Es la fase más pesada; no bloquea
las demás.

## Fase 4 — Adaptador Practilizate

**Objetivo:** reutilizar el dataset agregado de Practilizate como fuente
opcional de benchmarks, sin acoplar los productos.

**Alcance:** leer `data/processed/dashboard_dataset.csv` o una vista PostgreSQL;
mapear columnas; desactivado por defecto. Sin imports de código.

**Criterios de aceptación**

- [ ] Adaptador desactivado por defecto.
- [ ] Mapeo explícito de columnas y validación de tipos.
- [ ] Si falta el archivo, la app sigue funcionando.
- [ ] E2E con CSV y con vista PostgreSQL simulada.

## Fase 5 — Dashboard Power BI de embudo

**Objetivo:** visualizar el embudo guardada → postulada → entrevista → oferta.

**Alcance:** export de postulaciones, modelo PBIP/PBIR, capturas y filtros por
periodo. No recalcula el match ni duplica reglas del backend.

**Criterios de aceptación**

- [ ] PBIR válido y capturas de ambas páginas.
- [ ] Datos desde el export de PractiCV, no desde la base de la web.
- [ ] Filtros por estado y fecha.
- [ ] Sin PII en el PBIX de demo.

## Fuera de v0.2

- Múltiples versiones de CV y deploy público de la demo: **v0.3**.
- Traducción de docs internas al inglés: **v0.3**.
- Integración con Jira como dependencia del producto: descartada.
- Auto-postulación, scraping masivo y multiusuario: fuera de alcance.

## Orden y dependencias

1. Power Automate (hecho).
2. Bookmarklet (no depende de nadie).
3. Adaptador Practilizate (opcional, bajo riesgo).
4. Power BI (depende de los exports actuales).
5. Correos de alerta (OAuth, mayor esfuerzo).

Cada fase se cierra con su E2E, artefacto, `ROADMAP.md` actualizado y commit.
No se avanza con tests rojos ni se commitean datos reales.
